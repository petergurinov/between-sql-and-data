# Сбор итогового набора

После запуска программа создает `raw.csv` и `journal.jsonl`. Команда `summarize` строит техническую сводку по пяти основным раундам. Прогрев сохраняется в исходных данных как `round=0`, но не входит в основные показатели.

Каталог `results/` содержит проверенную версию результатов для публикации. `measurements.csv` и `measurements.xlsx` содержат одинаковые 5498 строк: 5475 фактических выполнений и 23 объявленных исхода без строки измерения. В таблице находятся метрики отдельных выполнений и принятые показатели варианта с префиксом `cell_*`.

Итоговый набор собирается в следующем порядке:

1. По журналу попыток выбирается одна принятая попытка каждого блока.
2. Прогрев, основные раунды, диагностические повторы и служебные измерения получают явную роль.
3. Проверяются число строк, `digest`, схема результата, полнота раундов и качество метрик.
4. Для основного окна рассчитываются медиана, минимум, максимум и отношение максимума к минимуму.
5. К измерениям добавляются условия запуска и описание способа чтения.
6. Добавляются поля `show_*_by_default`, в которых уже учтены правила качества.
7. Проверяются хеши файлов, отсутствие закрытых данных и повторяемость сборки CSV.

DataLens читает `results/measurements.csv`. Для показателей `cell_*` нужен фильтр `is_cell_anchor=true`; для графиков отдельных выполнений используются поля `show_*_by_default`. Настройка датасета описана в `results/DATALENS.md`.
