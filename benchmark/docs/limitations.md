# Ограничения

Результаты относятся к зафиксированным версиям СУБД и библиотек, выбранной схеме данных, аппаратным ресурсам и сети. Они не задают универсальный рейтинг протоколов. Два способа чтения могут одновременно различаться библиотекой, буферизацией, форматом, числом выделений памяти и моментом создания конечной структуры.

Для повторного эксперимента или новой публикации зафиксируйте:

- лицензию, источник и SHA-256 входных данных;
- версии СУБД, клиентов и DDL, а также настройки сессии;
- расположение клиента относительно серверов и наличие TLS;
- ограничение памяти, swap, фоновые процессы и состояние обслуживания таблиц;
- границы измерения времени для каждого способа чтения;
- статусы отказов и данные, по которым сделан вывод об ограничении памяти;
- принятую попытку блока целиком, без выбора лучших отдельных строк;
- назначение прогрева, основных раундов, повторов и служебных измерений;
- связь каждой цифры дашборда с исходной строкой измерения.

Не публикуйте секреты, адреса внутренней сети, имена машин и необработанную телеметрию. Крупные исходные файлы можно приложить к выпуску GitHub с SHA-256, а в Git хранить проверенный набор для анализа.
